The fixes

01 recorded[] lost its contents on every yield

was: protothread_core_0, line 232  →  now: file scope, line 92

Protothreads resume by jumping into a switch. The header does this:

#define LC_RESUME(s)  switch(s) { case 0:
#define LC_SET(s)     s = __LINE__; case __LINE__:

So on every resume, control lands on a case label past that declaration — its initialiser never runs again — and non-static locals sit on a stack the other threads reuse. The flags held whatever happened to be there.

What you saw: record and play behaving randomly. if (!recorded[record_key]) was a coin flip.

wasstatic int possible_key;
bool recorded[9] = {false};   // inside the thread
now// at file scope, beside record_length
// (later removed entirely - see fix 08)

02 Key 9 wrote past the end of every array

was: line 78  →  now: line 87

record_key takes the key number directly, so it ranges 1–9. Arrays of size 9 have valid indices 0–8. Pressing key 9 wrote one element past the end of recordings, record_length and recorded — into whatever variable happened to sit next in memory.

What you saw: nothing, until unrelated variables started changing on their own.

was#define NUM_RECORD_KEYS 9   // indices 0..8
now// Keys are numbered 1-9, so index N holds key N
// and slot 0 is simply unused.
#define NUM_RECORD_KEYS 10

Subtracting one everywhere works too. Wasting slot 0 means no subtraction exists to get wrong later.

05 The slider only reached 4095 Hz

lines 146 and 198  →  line 79

The raw ADC reading went straight into the frequency slot, so the pot reading was the pitch in hertz — capped at 4095. The checkpoint asks for 0–10 kHz, and a cardinal reaches 7 kHz, so the top of the sweep was unreachable.

now#define MAX_FREQ_HZ 10000.0f
static inline unsigned int adc_to_phase_incr(unsigned int adc) {
    float freq = ((float)adc * MAX_FREQ_HZ) / 4095.0f ;
    return (unsigned int)(((double)freq * two32) / Fs) ;
}

At the top of travel: adc 4095 → 10000.0 Hz → increment 858,993,459. Comfortably inside a 32-bit value, and well under the 25 kHz Nyquist limit.

06 The conversion existed in two places

protothread_toggle25 and protothread_playback

Recording and playback each did their own arithmetic. Fixing the range in one and not the other would have played every recording back at a different pitch than it was recorded at — a bug that looks like the storage is corrupted.

Both now call adc_to_phase_incr(). One definition, so they cannot drift.

10 Two threads toggled the same LED

lines 141 and 236  →  one owner

The ADC thread flipped GPIO 25 every 10 ms and the keypad thread flipped it every 30 ms. The flips interleaved, so the blink meant nothing — and a dead keypad thread would still have looked alive.

The keypad thread now owns it alone, and the duplicate #define LED 25 beside LED_PIN is gone. A steady blink now honestly means that thread is still being scheduled.

The pattern behind most of them

Five of the twelve are the same mistake in different clothes: the same fact stored in two places.

  • Two copies of the pot→pitch conversion
  • A recorded[] flag beside the length that already implied it
  • Two threads writing one pitch variable
  • Two threads owning one LED
  • Comments disagreeing with the code they sit above

Whenever you notice you are keeping a second copy of something the program already knows, expect the two to drift apart. Prefer deriving it to storing it again.
