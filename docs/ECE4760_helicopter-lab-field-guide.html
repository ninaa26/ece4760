What you are building

A one-direction helicopter. A small motor and propeller sit at the end of an arm that swings on a hinge. You type an angle, and the Pico runs the motor just hard enough to hold the arm there. A sensor on the arm (an IMU) measures the angle, a PID controller works out the motor power 1000 times a second, and the VGA screen plots the angle and the motor power live.

The big idea Think of holding a full glass of water at arm's length with your eyes open. Your eyes tell you where the glass is, your brain compares that with where you want it, and your arm pushes up a little more or less. That loop (measure, compare, push, repeat) is feedback control. Here the IMU is the eyes, the PID code is the brain, and the motor is the arm. PID is a recipe for "how hard to push": more if you're far off (P), more if you've been off for a while (I), and less if you're already moving fast toward the goal (D).
The handout is the spec. Hunter Adams' handout (PID control of a 1D helicopter) and the pages it links say what each week needs. Some of those pages still say RP2040; the same code runs on your Pico 2. The pins in this guide are the ones the course demos use. Where this guide and the handout disagree, the handout wins.

The loop, in one picture

In simple words Follow the arrows. Your target goes in at the top left. The Pico turns it into a motor power, the motor lifts the arm, the sensor on the arm measures the new angle, and that angle goes back into the controller. Round and round, every millisecond.

Which way is which angle

In simple words Angles are measured from level. Up is positive, down is negative. The arm starts hanging straight down, at −90°. The handout writes that as −1.57 radians (radians are another unit for angles: 90° is about 1.57).

The big idea PWM (pulse-width modulation) is how a pin that can only be fully on or fully off controls something "halfway". It flicks on and off very fast, and the motor feels the average. On 25 % of the time feels like a quarter of full power. It's like dimming a room by flicking the light switch faster than anyone can see.

You should see a square wave repeating every 1 ms (1 kHz), between 0 and 3.3 V. Type 3000: high half the time. Type 1500: high a quarter of the time. Type 0: flat at 0 V. Note that it's already at half before you type anything: step 2 fixes that.

How it works: the numbers

In simple words The PWM hardware has a counter that counts up to 6000 and starts again, over and over. The pin is high while the count is below your number and low after. Your number out of 6000 is the fraction of time it's on.
SettingIn the codeResult
System clock150 MHz (Pico 2 default)150 million ticks a second
Clock dividerCLKDIV 25.0fcounter steps 6 million times a second
Wrap valueWRAPVAL 60006000 steps = 1 ms, so 1 kHz
Levelpwm_set_chan_level(…, control)on for control/6000 of each 1 ms

Why only 1 kHz? The optoisolator on the motor board (step 3) is slow: it can't switch cleanly much faster. The handout picks 1 kHz for that reason. It also suits the controller: the PWM's wrap interrupt fires once per period, so 1 kHz PWM gives a 1 kHz control loop for free in week 2.

The interrupt. on_pwm_wrap() runs every time the counter wraps (every 1 ms). It clears its flag and, if you typed a new number, loads it. Changing the level only at the wrap means a pulse is never cut short halfway.

/**
 * V. Hunter Adams (vha3@cornell.edu)
 * PWM demo code with serial input
 * 
 * This demonstration sets a PWM duty cycle to a
 * user-specified value.
 * 
 * HARDWARE CONNECTIONS
 *   - GPIO 4 ---> PWM output
 * 
 */
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <string.h>

#include "pico/stdlib.h"
#include "pico/multicore.h"

#include "hardware/pwm.h"
#include "hardware/irq.h"

#include "pt_cornell_rp2040_v1_4.h"

// PWM wrap value and clock divide value
// For a CPU rate of 150 MHz, this gives
// a PWM frequency of 1 kHz.
#define WRAPVAL 6000
#define CLKDIV 25.0f

// GPIO we're using for PWM
#define PWM_OUT 4

// Variable to hold PWM slice number
uint slice_num ;

// PWM duty cycle
volatile int control ;
volatile int old_control ;

// PWM interrupt service routine
void on_pwm_wrap() {
    // Clear the interrupt flag that brought us here
    pwm_clear_irq(pwm_gpio_to_slice_num(PWM_OUT));
    // Update duty cycle
    if (control!=old_control) {
        old_control = control ;
        pwm_set_chan_level(slice_num, PWM_CHAN_A, control);
    }
}

// User input thread
static PT_THREAD (protothread_serial(struct pt *pt))
{
    PT_BEGIN(pt) ;
    static int test_in ;
    while(1) {
        sprintf(pt_serial_out_buffer, "input a duty cycle (0-6000): ");
        serial_write ;
        // spawn a thread to do the non-blocking serial read
        serial_read ;
        // convert input string to number
        sscanf(pt_serial_in_buffer,"%d", &test_in) ;
        if (test_in > 6000) continue ;
        else if (test_in < 0) continue ;
        else {
            control = test_in ;
            // Say what was set, so you know the Pico heard you
            sprintf(pt_serial_out_buffer, "duty %d of 6000 = %d%%\r\n", control, control / 60) ;
            serial_write ;
        }
    }
    PT_END(pt) ;
}

int main() {

    // Initialize stdio
    stdio_init_all();

    ////////////////////////////////////////////////////////////////////////
    ///////////////////////// PWM CONFIGURATION ////////////////////////////
    ////////////////////////////////////////////////////////////////////////
    // Tell GPIO PWM_OUT that it is allocated to the PWM
    gpio_set_function(PWM_OUT, GPIO_FUNC_PWM);

    // Find out which PWM slice is connected to GPIO PWM_OUT (it's slice 2)
    slice_num = pwm_gpio_to_slice_num(PWM_OUT);

    // Mask our slice's IRQ output into the PWM block's single interrupt line,
    // and register our interrupt handler
    pwm_clear_irq(slice_num);
    pwm_set_irq_enabled(slice_num, true);
    irq_set_exclusive_handler(PWM_IRQ_WRAP, on_pwm_wrap);
    irq_set_enabled(PWM_IRQ_WRAP, true);

    // This section configures the period of the PWM signals
    pwm_set_wrap(slice_num, WRAPVAL) ;
    pwm_set_clkdiv(slice_num, CLKDIV) ;

    // This sets duty cycle
    // Start with the motor OFF. The demo started at 3000 (half power),
    // which would spin the motor as soon as the Pico powers up.
    pwm_set_chan_level(slice_num, PWM_CHAN_A, 0);

    // Start the channel
    pwm_set_mask_enabled((1u << slice_num));

    ////////////////////////////////////////////////////////////////////////
    ///////////////////////////// ROCK AND ROLL ////////////////////////////
    ////////////////////////////////////////////////////////////////////////
    pt_add_thread(protothread_serial) ;
    pt_schedule_start ;

}

Step 3

Solder the motor board

Goal: the motor driver circuit built on its printed circuit board, checked with a multimeter before any power goes on.

The big idea The Pico's pin can't power a motor: it gives a few thousandths of an amp and the motor wants around an amp. So the pin only flicks a switch, and the switch connects the motor to its own power supply. The switch here is a MOSFET, and between the Pico and the MOSFET there's a light beam (inside the optoisolator), so the motor's electrical mess can't travel back down a wire into the Pico.

Solder

  1. Low parts first, so the board sits flat while you solder: the resistors (match each value to its label on the board: 330, 1M, 10k, 10k), then the diode.
  2. Diode: the stripe on the diode goes on the stripe of the outline printed on the board. Backwards, it short-circuits the motor supply the first time the motor is switched on.
  3. 4N35: the small dimple marks pin 1. Match it to the notch or dot printed on the board.
  4. Capacitor (either way round), then the MOSFET with its pins in the order G, D, S as printed on the board.
  5. Screw terminals, barrel jack, killswitch last.

Check before power

Multimeter on continuity (the beep setting):

  • No beep between the 12 V terminal and the power-supply GND terminal.
  • No beep between the PWM terminal and the MCU GND terminal (a short here would short the Pico's pin).
  • No beep between MCU GND and power-supply GND: the two sides really are separate.
  • No solder bridges between neighbouring pins on the 4N35 (look with a magnifier).

Why the spikes are so big

In simple words A motor is a coil of wire, and a coil hates sudden changes in current, like a heavy cart that doesn't want to stop. Switch the current off in a hurry and the coil makes a huge voltage to keep it flowing. The diode gives that current a safe loop to fade away in.

The handout's example: a coil's voltage is V = L × dI/dt. A motor with L = 1 mH carrying 1 A, switched off in 10 ns, gives 10⁻³ × 1 / 10⁻⁸ = 100 000 V in principle. In practice something breaks down long before that, which is exactly what the diode is there to prevent.

The handout's puzzle: the board has one more 10 kΩ resistor than the schematic. What is it for? Trace its two pads on the board to see what it connects, and work it out; the TA may ask.

Step 4

Build the arm

Goal: the arm swings freely on its hinge, the motor is held firmly at its end, and the wires won't fight the motion.

The big idea The controller can only fix what it measures. Anything mechanical that changes from minute to minute (a hinge that sticks, a wire that pulls, a loose motor that wobbles) looks to the controller like a mysterious force, and makes tuning much harder. A minute spent making it solid now saves an hour of tuning in week 3.

Word list

PWM
Pulse-width modulation: a pin switched on and off at a fixed rate, where the on-fraction (duty cycle) sets the average.
Duty cycle
The fraction of each period the pin is high. Here, your number out of 6000.
Slice, channel
The RP2350's PWM is split into slices with one counter each; each slice has two outputs, A and B. GP4 is slice 2, channel A.
Wrap
When the PWM counter reaches its top value and starts again. It can trigger an interrupt.
UART
The two-wire serial link (TX and RX) to the laptop, through the USB-to-serial adapter.
Baud rate
Serial speed in bits per second. Both ends must agree: 115200.
Optoisolator
An LED and a light sensor in one chip: passes a signal with no electrical connection.
MOSFET
A transistor used as a power switch. Voltage on the gate lets current flow from drain to source.
Flyback (snubber) diode
A diode across a coil that carries its current when switched off, preventing a voltage spike.
Open loop
Setting an output without measuring the result.

Step 1

Wire the IMU and run its demo

Goal: the IMU talking to the Pico, its six readings on the screen, and a note of which of its axes points which way on your arm.

The big idea The IMU is two sensors in one chip. The accelerometer feels which way gravity pulls, like a plumb line. The gyroscope feels how fast it's turning, like the feeling of spinning on an office chair. Each measures along three directions, x, y and z, fixed to the chip. Before using them you need to know which of those directions lines up with your arm.

Find your axes

The colours are x = white (0), y = red (1), z = green (2). On the bottom plot, 1 g is about halfway between 0 and the +2 label. Do these three tests and fill in the table; step 2 needs it.

  1. Hold the arm level and still. The accelerometer trace near +1 g is the up axis: UP_SIGN is +1. If one sits at −1 g instead, that's the up axis upside down: UP_SIGN is −1.
  2. Let the arm hang straight down. A different trace moves to ±1 g: that's the along-the-arm axis. At −1 g it points out toward the motor: ARM_SIGN +1. At +1 g it points back to the hinge: ARM_SIGN −1.
  3. Lift the arm quickly by hand. One gyro trace jumps (the axis along the hinge). Jumps up: GYRO_SIGN +1. Down: −1.

The demo's interrupt flips GP14 · 19 every time it runs. Probe it: a square wave at 500 Hz (it flips once per 1 ms interrupt, so a full up-down takes 2 ms) means the interrupt really runs at 1 kHz. That interrupt is where the angle and the controller will live.

Step 2

Turn the readings into one angle

Goal: a single, steady number for the arm's angle, in degrees, on the screen. −90 hanging, 0 level.

The big idea You have two ways to know the angle, and each is bad in a different way. The gyro is like walking with your eyes closed and counting steps: very accurate over a few seconds, but small errors add up and you slowly drift off course. The accelerometer is like glancing at a plumb line on a bumpy bus: always right on average, but jumpy, and the motor's shaking makes it worse. The complementary filter walks by counting steps (gyro) and keeps glancing at the plumb line (accelerometer) to correct the drift. Each covers the other's weakness.

What it does
  • fix2float15 turns the library's fixed-point reading into a normal decimal number: g for the accelerometer, degrees per second for the gyro.
  • Step 2 is the same low-pass as the handout's motor display: move a small fraction (5 %) of the way toward each new reading.
  • atan2f(along, up) gives the angle of the gravity arrow, in radians, the right way round in every quarter of the circle. Level: along = 0, up = 1, so 0°. Hanging down: along = −1, up = 0, so −90°.
  • Step 5 is the complementary filter: 99 % "where I was, plus what the gyro says I turned in 1 ms" and 1 % "what gravity says". The 1 % slowly pulls any gyro drift back to the truth.
  • The first sample sets the angle straight from gravity, so it doesn't start at 0 and take a second to swing round.

// Interrupt service routine
void on_pwm_wrap() {

    // Clear the interrupt flag that brought us here
    pwm_clear_irq(pwm_gpio_to_slice_num(5));
    gpio_put(14, !gpio_get(14)) ;

    // Read the IMU
    // NOTE! This is in 15.16 fixed point. Accel in g's, gyro in deg/s
    // If you want these values in floating point, call fix2float15() on
    // the raw measurements.
    mpu6050_read_raw(acceleration, gyro);

    // --- Estimate the arm angle ---
    // 1. This sample's accelerometer readings along the arm and "up", in g
    float arm_now = ARM_SIGN * fix2float15(acceleration[ARM_AXIS]) ;
    float up_now  = UP_SIGN  * fix2float15(acceleration[UP_AXIS]) ;
    if (!angle_started) {
        arm_g = arm_now ;
        up_g  = up_now ;
    }
    // 2. Smooth them: the motor shakes the accelerometer
    arm_g += ACCEL_SMOOTH * (arm_now - arm_g) ;
    up_g  += ACCEL_SMOOTH * (up_now  - up_g) ;
    // 3. Angle from gravity alone: noisy, but it never drifts
    float accel_angle = atan2f(arm_g, up_g) * RAD_TO_DEG ;
    // 4. Turn rate from the gyro, degrees per second: smooth, but it drifts
    angle_rate = GYRO_SIGN * fix2float15(gyro[GYRO_AXIS]) ;
    // 5. Blend: last angle + what the gyro says we turned, nudged toward gravity
    if (!angle_started) {
        angle = accel_angle ;
        angle_started = 1 ;
    }
    angle = (1.0f - ACCEL_WEIGHT) * (angle + angle_rate * DT) + ACCEL_WEIGHT * accel_angle ;

    // Increment drawspeed controller
    throttle += 1 ;
    // Maintain a circular buffer for display
    if ((throttle >= threshold)) { 
        // Zero drawspeed controller
        throttle = 0 ;

        // Replace oldest data in accel arrays with new sample
        ax[head] = acceleration[0] ;
        ay[head] = acceleration[1] ;
        az[head] = acceleration[2] ;

        // Replace oldest data in gyro arrays with new sample
        gx[head] = gyro[0] ;
        gy[head] = gyro[1] ;
        gz[head] = gyro[2] ;

        // Move the pointer to the oldest data
        head = ((head+1) == PLOT_WIDTH) ? 0 : (head + 1) ;

    }
}

// Interrupt service routine
void on_pwm_wrap() {

    // Clear the interrupt flag that brought us here
    pwm_clear_irq(pwm_gpio_to_slice_num(5));
    gpio_put(14, !gpio_get(14)) ;

    // Read the IMU
    // NOTE! This is in 15.16 fixed point. Accel in g's, gyro in deg/s
    // If you want these values in floating point, call fix2float15() on
    // the raw measurements.
    mpu6050_read_raw(acceleration, gyro);

    // --- Estimate the arm angle ---
    // 1. This sample's accelerometer readings along the arm and "up", in g
    float arm_now = ARM_SIGN * fix2float15(acceleration[ARM_AXIS]) ;
    float up_now  = UP_SIGN  * fix2float15(acceleration[UP_AXIS]) ;
    if (!angle_started) {
        arm_g = arm_now ;
        up_g  = up_now ;
    }
    // 2. Smooth them: the motor shakes the accelerometer
    arm_g += ACCEL_SMOOTH * (arm_now - arm_g) ;
    up_g  += ACCEL_SMOOTH * (up_now  - up_g) ;
    // 3. Angle from gravity alone: noisy, but it never drifts
    float accel_angle = atan2f(arm_g, up_g) * RAD_TO_DEG ;
    // 4. Turn rate from the gyro, degrees per second: smooth, but it drifts
    angle_rate = GYRO_SIGN * fix2float15(gyro[GYRO_AXIS]) ;
    // 5. Blend: last angle + what the gyro says we turned, nudged toward gravity
    if (!angle_started) {
        angle = accel_angle ;
        angle_started = 1 ;
    }
    angle = (1.0f - ACCEL_WEIGHT) * (angle + angle_rate * DT) + ACCEL_WEIGHT * accel_angle ;

    // --- Drive the motor ---
    pwm_set_chan_level(slice_num, PWM_CHAN_A, motor_cmd) ;
    // Smooth the command for the screen (the handout's low-pass, about 16 samples)
    motor_disp = motor_disp + ((motor_cmd - motor_disp) >> 4) ;

    // Increment drawspeed controller
    throttle += 1 ;
    // Maintain a circular buffer for display
    if ((throttle >= threshold)) { 
        // Zero drawspeed controller
        throttle = 0 ;

        // Replace the oldest sample with the newest
        angle_hist[head] = angle ;
        motor_hist[head] = motor_disp ;

        // Move the pointer to the oldest data
        head = ((head+1) == PLOT_WIDTH) ? 0 : (head + 1) ;

    }
}

Step 4

Close the loop

Goal: you type an angle and the Pico holds the arm there by itself, with gains you set over serial.

The big idea Think of cruise control on a car going up and down hills. P (proportional): the slower you are than the target, the harder you press the pedal. I (integral): if you've been a bit slow for a while, press a little harder still, until the slowness is gone. D (derivative): if you're already speeding up fast, ease off before you overshoot. Each gain (Kp, Ki, Kd) says how strongly to apply that rule.

What it does

  • I: each sample adds Ki × error × 0.001 s. A small error that lasts keeps adding up until the motor pushes enough to fix it. Storing it already multiplied by Ki means changing Ki doesn't make the motor jump. Keeping it between 0 and 6000 is anti-windup: it can't pile up to a huge value while the arm is stuck.
  • D: the derivative of the error is minus the arm's turning speed (the target isn't moving), and the gyro measures that speed directly. So D is −Kd × angle_rate: no subtracting noisy angles needed.
  • The motor can't pull the arm down, so anything below 0 becomes 0. Gravity does the pulling down.
  • When pid_on is 0 this whole block is skipped and motor_cmd keeps whatever m set.

// Interrupt service routine
void on_pwm_wrap() {

    // Clear the interrupt flag that brought us here
    pwm_clear_irq(pwm_gpio_to_slice_num(5));
    gpio_put(14, !gpio_get(14)) ;

    // Read the IMU
    // NOTE! This is in 15.16 fixed point. Accel in g's, gyro in deg/s
    // If you want these values in floating point, call fix2float15() on
    // the raw measurements.
    mpu6050_read_raw(acceleration, gyro);

    // --- Estimate the arm angle ---
    // 1. This sample's accelerometer readings along the arm and "up", in g
    float arm_now = ARM_SIGN * fix2float15(acceleration[ARM_AXIS]) ;
    float up_now  = UP_SIGN  * fix2float15(acceleration[UP_AXIS]) ;
    if (!angle_started) {
        arm_g = arm_now ;
        up_g  = up_now ;
    }
    // 2. Smooth them: the motor shakes the accelerometer
    arm_g += ACCEL_SMOOTH * (arm_now - arm_g) ;
    up_g  += ACCEL_SMOOTH * (up_now  - up_g) ;
    // 3. Angle from gravity alone: noisy, but it never drifts
    float accel_angle = atan2f(arm_g, up_g) * RAD_TO_DEG ;
    // 4. Turn rate from the gyro, degrees per second: smooth, but it drifts
    angle_rate = GYRO_SIGN * fix2float15(gyro[GYRO_AXIS]) ;
    // 5. Blend: last angle + what the gyro says we turned, nudged toward gravity
    if (!angle_started) {
        angle = accel_angle ;
        angle_started = 1 ;
    }
    angle = (1.0f - ACCEL_WEIGHT) * (angle + angle_rate * DT) + ACCEL_WEIGHT * accel_angle ;

    // --- PID: work out the motor command from the angle ---
    if (pid_on) {
        // How far off are we? Positive = the arm is too low
        float error = target - angle ;
        // I: add up the error over time (stored already multiplied by Ki)
        i_term += Ki * error * DT ;
        if (i_term > WRAPVAL) i_term = WRAPVAL ;   // don't let it grow forever
        if (i_term < 0) i_term = 0 ;
        // P + I + D. For D, the gyro already measures how fast the angle changes
        float out = Kp * error + i_term - Kd * angle_rate ;
        // The motor can only push up, from off to full power
        if (out < 0) out = 0 ;
        if (out > WRAPVAL) out = WRAPVAL ;
        motor_cmd = (int)out ;
    }

    // --- Drive the motor ---
    pwm_set_chan_level(slice_num, PWM_CHAN_A, motor_cmd) ;
    // Smooth the command for the screen (the handout's low-pass, about 16 samples)
    motor_disp = motor_disp + ((motor_cmd - motor_disp) >> 4) ;

    // Increment drawspeed controller
    throttle += 1 ;
    // Maintain a circular buffer for display
    if ((throttle >= threshold)) { 
        // Zero drawspeed controller
        throttle = 0 ;

        // Replace the oldest sample with the newest
        angle_hist[head] = angle ;
        motor_hist[head] = motor_disp ;
        target_hist[head] = target ;

        // Move the pointer to the oldest data
        head = ((head+1) == PLOT_WIDTH) ? 0 : (head + 1) ;

    }
}

The big idea With P alone the arm will settle below the target, and that's expected. P only pushes when there's an error. Holding the arm up takes about the hover duty, so the arm has to sag until Kp × error equals the hover duty. A bigger Kp needs less sag to push the same, but past some point the arm starts to bounce. I removes the sag (week 3).

Why not use only the accelerometer?Noisy, especially with the motor shaking it.

A small constant error in the gyro's reading. Added up over time it becomes drift.
Complementary filter
A weighted blend of the gyro's angle (good short-term) and the accelerometer's (good long-term).
Low-pass filter
Keeps slow changes, smooths away fast jitter. Here: move a fraction of the way toward each new reading.
atan2(y, x)
The angle of the arrow (x, y), correct in all four quarters of the circle.
I²C
Two-wire bus (SDA data, SCL clock) where each chip has an address.
Closed loop
Measuring the result and correcting the output from it: feedback.
Error
Target minus measured angle.
P, I, D
The three terms: proportional to the error, to its running total, and to how fast it's changing.
Gain
How strongly a term acts: Kp, Ki, Kd.
Integral windup
The I term growing huge while the arm can't move. Clamping it to 0–6000 prevents it.
Settling time
How long after a target change the arm takes to stay within a small band of its final angle.
Floating point
Numbers with a decimal point (float). The RP2350 has hardware for them, so they are fast enough here.
